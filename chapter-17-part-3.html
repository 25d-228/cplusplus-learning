Chapter 17 — Grouping, checked aggregates, and complete queries

Part 3 — Boundary, failure, and two-sort checks

This part turns the implementations from Part 1 and Part 2 into runnable checks. Append every segment for a named file in order. Keep every earlier test. No database/query implementation is supplied by Python: it independently computes expected answers and decodes the actual native temporary files.

The test oracle is deliberately allowed to use std::map and ordinary vectors. The production pipeline is not. We use small inputs to compare values exactly; this is not a claim that the oracle follows the engine's memory bound. Its separate storage also lets a test reserve the engine's remaining budget without preventing the test harness from recording an answer.

Define the harness and its borrowing contract

The temporary-directory helper owns only paths it just created and removes them on normal scope exit. Its cleanup is test convenience, not the production sink's error-reporting contract. The check function remains active in Release builds; none of the required checks depends on assert surviving NDEBUG.

Source borrows its input span from a fixture that outlives the plan. It copies rows into the output, can interleave empty progress batches, and can violate the EOF protocol deliberately. A Probe counts calls, making it possible to prove that preflight rejection happens before consumption. In production, the sources are the owning scans/sorts/join from the preceding parts.

The oracle groups by a pair independently of the streaming state machine. It checks arithmetic before incrementing; no expected answer is generated by calling add_event. The sorting helper spells out tuple fields independently of JoinedOrder. The drain helper limits calls so a nonprogressing state machine fails rather than hanging the test indefinitely.

Use small capacities deliberately. Three-row generation and a three-descriptor allowance force two-way merge passes; these are not arbitrary large buffers that accidentally let a whole fixture fit. The seven initial mutations reproduce the roadmap's accounts, matching events, unmatched event, and excluded day.

Check arithmetic independently of input scale

To reach an unsigned 64-bit count overflow through real rows would exceed the course's explicit sort caps by many orders of magnitude. Seed the accumulator at the boundary and test the transition directly. Sum overflow, however, is reachable with two high-value events and is tested through the complete query below.

The two checked values must commit together: failing the sum after computing a candidate count may not change the installed count. Four deterministic allocation failure positions cover all group columns. The exact 48-byte charge is two rows times 24 column bytes, not the size of the enclosing GroupBatch object.

Vary input, output, and work boundaries independently

The 54 combinations use three input capacities, three output capacities, three work quotas, and the presence/absence of interleaved empty batches. The fixture contains a 53-row leading group, many later groups, and maximum unsigned key/ID fields. The expected final group is essential: there is no following key to trigger its emission.

The separate 4097-row hot-group test gives the aggregate a two-row input buffer and one-row output, then reserves every remaining covered byte. Draining must succeed without acquiring additional engine memory. This proves the aggregate itself does not grow with the group, not that a full sorter can run with no spare workspace.

Fail after useful work, not only at construction

One fixture first returns a valid group in a separate owning batch. A later call finishes another group and then overflows a third. That call's entire output must clear; the earlier batch remains intact. Another pull must reject as terminal without touching an intentionally installed sentinel.

Descending keys cross one-row refills. A nonempty EOF is rejected. Foreign-budget output is rejected with zero source calls. A move after an empty quota-limited return preserves the unfinished group. Use only the moved-to plan afterward; the moved-from plan is for destruction or reassignment, not continued pulling.

Reexercise the shared sorter with joined values

The 25-row fixture produces nine initial joined runs, three materialized passes, and sixteen completed files. Every field participates in the independent equality check. Then fail each charged acquisition in turn until a complete run succeeds. For every failed attempt, the scope must close descriptors, release all charges, and remove successfully deletable private run names.

The number of failing acquisition ordinals is an observation of this build, not a portable API promise. A different standard library can change control-block sizes or the allocation sequence. The invariant is cleanup and exact answers at every exercised position, not a hard-coded count of 40.

The next hook changes the joined run's ordering ID to the event ordering ID and recomputes a valid header checksum. This is not a random-bit checksum test: it specifically checks the typed interpretation boundary. A reinterpret_cast here lets the test stream read/write the object representation of a byte array; it does not reinterpret those bytes as an aligned native record. The actual decoding remains explicit little-endian operations.

Check complete query status separately from accepted rows

CollectSink is a test consumer that retains accepted groups and records finish or abort. Unlike CsvResult, it cannot retract its vector merely by setting aborted; that is intentional. Its prefix is not a complete answer unless its completion flag is true. read_text is a test-only whole-file helper, not part of the streaming engine.

The old plan is paused after emitting (1,3,2,750). By then the second sorter has copied every joined row and released its upstream snapshot and first-sort files. Write the roadmap's atomic update, flush, compact, and collect; the old plan's remaining answer is still (2,3,1,700). The new query must emit exactly (3,3,2,1400): two events remain in account 10's new region, with amounts 500 and 900; event 102 is deleted.

This is more than keeping the database object alive. It demonstrates that already materialized joined values retain their meaning after storage generations become reclaimable. A deliberately rejecting sink then checks the independent failure status and upstream release path.

Keep an old completed result through output failure

The output hook can fail before a line write, before close, or before rename. In the write case the header and first group have already been accepted; the second group fails. The completed destination must remain the literal old content, and no new temporary may remain after successful cleanup. The staged-group report is one for that case and two for the two later boundaries.

These hooks test the application's ordering and cleanup responses. A hook before close is not a physical filesystem close-error simulation, nor is a hook before rename a power-loss experiment. Chapter 6 separately tests partial I/O. Explicit unlink refusal here verifies that an unresolved temporary is reported and that a later cleanup retry can confirm absence.

The full-query allocation campaign includes statistics controls, both sorts, batches, and source construction. A retained caller view establishes a baseline; a failed temporary plan must return to that baseline after its report dies. Keeping the report alive could legitimately keep statistics/control allocations charged, so the check occurs after its scope.

The next test causes real sum overflow in the joined query, after one earlier group has been accepted by the sink. The destination still contains its prior completed value. An independent escaped-plan test destroys both the database and the caller's root-budget handle before pulling; the complete ownership chain must support a new query operation and eventually release its last ledger owner.

Capture completed native runs for an independent reader

The hook copies completed files into separate test-only directories before the sort can retire them. These copies are oracle artifacts, outside the engine's resource ledger and normal temporary-file cleanup. They are not query checkpoints or recovery candidates. Their parent is deleted by the outer Python fixture.

The larger fixture begins with 31 accounts and 210 events, then deletes one account and one event and changes event 9. Filtering days [2,6) leaves 119 events; the inner join produces 100 rows and regional/day grouping produces 20 groups. Account 12's deleted row must not participate. The event update must appear once, with 888 cents and day 2 rather than its earlier values.

Both sorts must spill and perform multiple materialized passes. Their input cardinalities differ because unmatched events disappear at the join. A second complete execution compares a separate C++ map oracle with all emitted groups.

Finish the test program. The optional --fixture ROOT mode leaves files for the external decoder; ordinary tests use a private temporary root and clean it up. Errors produce a nonzero process status rather than a successful-looking line.

Decode actual bytes without importing the C++ codec

Create scripts/check_query_fixture.py. It uses Python's explicit little-endian struct layouts, CRC-32, integer arithmetic, and a dictionary of expected groups. The header identifies width 28/order 1 or width 32/order 2. The script checks all frames and footers, exact byte coverage, row counts, and appropriate ordering. This intentionally does not call the engine's decoder to verify its own output.

The independent fixture applies the same input mutations using dictionaries keyed by record ID. Python integers do not wrap at 64 bits. The ordinary fixture fits comfortably in the required unsigned result range; the separate C++ overflow checks establish the engine's rejection policy.

For each sort, the first recorded files are its initial runs. Their multiset must equal the entire corresponding input, including multiplicities. Every captured intermediate run must contain only legitimate source occurrences and be correctly ordered; the final CSV provides the end-to-end completeness check. All 144 captured files are decoded, not only the final run.

The driver is exercised with spilling, no-spill, and empty plans. Invalid bounds and trailing characters must fail without replacing an existing completed file. The empty query publishes only the header and reports zero groups.

Build the two new checks

Append the following to root CMakeLists.txt; do not replace its existing targets or repeat the old external_sort.cpp source registration. The existing core target already compiles that file, which Part 1 replaced. CMake's Python interpreter variable was established in the earlier fixture chapters.

From the implementation root, build both ordinary configurations. Use your compatible native C++20 compiler from Chapter 1; changing it requires a fresh build directory. Do not force an x86 architecture on the M4.

Both configurations should pass all 25 CTest entries. The two new entries are aggregate-query and complete-query-native. The focused program reports the following values; the two allocation-failure counts are observations rather than cross-toolchain constants.

The Python check ends with independent oracle: 144 native files; 119 events; 100 joins; 20 groups; CLI tiny/default/empty pass. The tiny driver reports 40 and 34 initial runs, while the default driver reports zero for both. On the checked Linux build, the respective root peak charges were 95,320 and 558,362 bytes. Those measurements include database/query charges and reflect different eagerly allocated capacities. They are not portable object-size promises, RSS values, throughput results, or evidence that spilling is always faster or smaller.

Inspect one concrete completed answer

Generate a disposable native fixture, then invoke the driver directly. The fixture command creates its own db and spill children and also leaves captured run copies; ordinary driver use does not create those copies.

Expect the header region_id,day,event_count,total_cents followed by increasing region/day pairs. The independent decoder, not a visual glance at the first five rows, establishes all 20 answers. The output file contains cents as exact integers; formatting them as currency belongs at a presentation boundary, not inside the aggregation loop.

Make one logical defect visible

In GroupAggregate<Source>::next, replace only the EOF line if (current_) { output.append(*current_); current_.reset(); } with if (current_) { current_.reset(); }. Rebuild strata-aggregate-tests and run it. The shape check must fail with aggregate differs from map oracle, including final group. This defect may leave every allocation valid and still lose an entire result group.

Restore the exact original line, rebuild, and rerun the full suite before continuing. A second focused exercise is to assign group.event_count before checking the sum in add_event. The sum-overflow test must reject that weaker failure guarantee. Restore it too; unsigned wraparound and premature publication are not repaired by enabling a memory sanitizer.

Use a separate sanitizer build where your toolchain supports it:

All 25 tests passed in fresh reconstructed Debug, Release, and AddressSanitizer/UndefinedBehaviorSanitizer builds with Clang 17 on Linux. Linux leak checking was enabled. The omitted-final-group variant failed its logical assertion in all three configurations without a sanitizer memory-error report; correct code was restored before the final passing runs. The acquisition counts and peaks above come from that environment. Native M4/macOS execution remains unverified. Unsupported platform diagnostics are not equivalent to passing ones.

Diagnose by boundary

Symptom First place to inspect
A region/day appears twice The joined sort order must begin with both grouping fields; inspect all comparator sites, not only chunk sorting.
Exactly the last group is missing Inspect EOF emission, including the nonempty-last-batch/empty-next-EOF pair.
First event of each later group is missing or doubled Trace the key-change row, current-group initialization, and source-index increment.
Failure returns a changed count with the old sum Both checked candidate totals must precede either assignment.
A paused result changes after an account update Both scans must share one read view; spill must preserve region, not look it up later.
“Workspace cannot make progress” Include control storage, stack allowance, sizeof(Row) generation, and three frames; more root memory does not override a smaller operator limit.
The final CSV changes after a failed query Do not open/truncate the final name in begin; completion must follow valid EOF and close.
Temporary name survives an exception Inspect reported unlink errors and retry only after the cause is resolved; do not hide or release an unresolved disk charge.

Completion check and references

You now have one complete fixed query, not a general SQL engine. It consumes one snapshot; external sorting and streaming join/grouping do the execution; bounded owning output batches feed a completion-aware sink. Both sorts can spill beyond their row buffers. No final result vector or unbounded group hash table exists in the production path. The public implementation remains synchronous, and the CSV completion boundary is not a durable recovery checkpoint.

The references actually used for the language and system boundaries are the C++ ordering rules, dependent-name rules, unsigned integer rules, exception propagation, and integer from_chars, together with Apple's archived temporary-file creation and rename interface. The evolving C++ draft is used only for facilities available in the chosen C++20 baseline. The Apple archive is not a substitute for checking the installed native manuals, compiler, filesystem, and test results. Resource bounds, traces, formats, and observed counts in this chapter are derived from the implementation and its checks, not asserted by those references.

Chapter 18 develops synchronization and thread lifetime in standalone runnable programs before the engine begins sharing these owners between workers. Do not add threads to the current budget, cache, database, or result sink merely because some of their handles use shared ownership.
