Chapter 17 — Grouping, checked aggregates, and complete queries

Part 2 — Keep one group; publish one complete result

Continue from Part 1. Its joined sorter preserves account, amount, day, event ID, and region while placing each region/day group contiguously. Now the aggregate can be smaller than either sort: one unfinished group, one previous row for order validation, and a bounded input batch. The output batch owns every completed group.

Count and sum are one state change

For group g, let I_g be the occurrences of joined rows with key g. Define its count n_g and total cents s_g by

n_g=|I_g|,\qquad s_g=\sum_{i\in I_g} v_i.

The empty stream has no groups. It does not emit (0,0,0,0). A group with zero total is legitimate when it contains one or more zero-cent events. Both outputs use uint64_t; the keys use uint32_t. Their maximum total is M=2^{64}-1=18446744073709551615.

Before incorporating amount v, require n_g<M and v\le M-s_g. Only then can we install (n_g+1,s_g+v). Reusing Chapter 6's checked addition twice computes the two candidate values before either assignment. For example, count 2 and sum M can accept another zero-cent event, but not a one-cent event. On the latter failure, count must remain 2, not 3.

Unsigned wraparound is defined modulo a power of two by the C++ fundamental type rules, but it is not an acceptable financial total. An unsigned-overflow bug may produce no undefined-behavior sanitizer report. This chapter deliberately rejects overflow instead of saturating, silently wrapping, or switching to floating point.

Own the output columns

GroupRow is an owning scalar value. GroupBatch contains four independently charged arrays: region and day at four bytes each, count and cents at eight bytes each. Capacity O therefore costs 24O column bytes, irrespective of sizeof(GroupRow) or its padding. rows_ identifies initialized visible entries, not allocated capacity. The member functions follow the existing batch contracts.

The implementation validates capacity before allocating. Construction failure unwinds already constructed columns. Move construction exchanges scalar lengths with zero and transfers columns with their matching budget owners. Move assignment uses a temporary and nonthrowing swap so the old allocations are released under their original owners. Self-move is a no-op. As for prior batches, a moved-from batch is reusable only after assigning valid storage; it is not a detached budget factory.

A replacement creates all four new arrays before swapping. A failed replacement therefore preserves the old rows and charge. A successful replacement intentionally clears the logical contents. append writes all four scalar fields before publishing the increased row count. This publication is a synchronous invariant, not an atomic operation for multiple threads.

Make boundaries explicit

The aggregation inputs own the upstream source and a joined batch. current_ exists only after seeing a first row. previous_ validates the complete joined ordering across refills. Neither optional grows with the number of rows or groups. The copied previous row is a validation aid, not a second accumulator.

A positive work quota limits rows consumed inside this loop per call. It can return an empty progress batch in the middle of a large group. It cannot limit the time an upstream sort takes to produce its next batch. The entire pipeline is still synchronous and noncancellable.

Consider sorted group keys A,A,B,B,C and output capacity one. On reading the first B, emit completed A, initialize B, and incorporate that same boundary row before returning. The next call resumes with one B already counted. If instead the cursor advanced without retaining that row, the first event of every later group would disappear.

The converse error is failing to consume the boundary row: it would be included twice. The source index advances exactly once, after add_event succeeds. On failure the whole stream is terminal, so no recovery path needs to guess whether a partly processed row should be replayed.

At EOF there is no next key to trigger a transition. Explicitly emit current_ once, release the upstream owner, and mark ended. If that emission returns a nonempty batch, the following call returns empty EOF. An empty upstream batch must not flush current_; the same group can continue afterward.

The input reference is borrowed from the optional. The EOF branch destroys that optional, then immediately returns without using input again. Similarly, the catch path never reads it after cleanup. value is copied before any source refill. These details make early destruction compatible with ordinary references.

An order error, refill exception, or overflow clears this call's output, releases upstream sources, and sets terminal failure. An earlier, separate owning batch remains readable. Thus a caller can observe a valid prefix before learning that the query failed. A sink must not confuse that prefix with a complete answer. The preflight check_output sits outside the try: a foreign-budget output or already-failed stream rejects before altering the caller's sentinel batch.

What remains live at each phase?

Let U be the upstream scan/filter/project batch capacity, E the join's event input capacity, A its account input capacity, J the second sort's joined-input capacity, G the aggregate input capacity, and O its output capacity. During second-sort generation the owning column arrays can total

100U+28E+12A+32J+32G+24O.

The 100U is Chapter 16's filter input (36), projection input (36), and first-sort input (28) per row. It excludes both sort cores, row chunks, frame buffers, metadata, snapshots, and the database. Add those actual charged allocations; do not assume a “100-byte row” is a universal pipeline footprint.

After second-sort generation, the join/scans/first-sort columns disappear. The aggregate needs 32G+24O column bytes plus the second sort's workspace and its constant scalar state. Its own storage is O(G+O), independent of the size of one group and the total number of groups. At valid EOF it releases the second sort too. Output batches, caller-held sort statistics, and any caller-held snapshot can still keep charges alive. Standard exception storage, test oracles, allocator metadata, and kernel caches are not all part of this ledger.

The sink contract separates acceptance from completion

begin establishes a fresh result attempt. append accepts a complete group, not the query. finish publishes successful completion only after valid EOF. abort is idempotent and nonthrowing. A generic consumer may be unable to retract accepted rows; it must still identify them as a failed query prefix.

A crucial implementer contract is that finish must not throw after committing publication. Otherwise a caller could report failure after the completed artifact was already installed. Our CSV sink performs all throwing work before rename succeeds, then only assigns scalar state. Hooks may throw before the named boundary, never after publication.

The sink below uses a trusted, stable private output directory and one validated basename. It is not a sandbox for hostile directory replacement, a shared-directory security service, or a cross-filesystem transaction. The filename limits are explicit fixed capacities, not guessed filesystem limits. The OS may reject a name even below our 512-byte path storage bound.

consume_results owns its plan by value. On return or unwinding, that ownership releases the pipeline even when the caller has not manually walked every source. Its staged_groups counter advances only after a sink accepts a row. It does not count bytes, and a sink write can fail after transferring only part of a line. All accepted rows remain provisional until finish succeeds.

Write under a temporary name, not the final one

The sink constructs two paths in its fixed arrays: the requested final basename and a same-parent .strata-result-XXXXXX template. A caller must not choose that temporary prefix as its result basename. No filesystem operation occurs in the constructor. The already completed destination, if any, remains untouched while the new query runs.

mkstemp creates and opens a unique file in one operation and modifies its writable template. Apple's archived mkstemp manual describes the returned descriptor and creation mode 0600. This avoids a separate existence-check/open sequence. Use a private output parent as well; safe temporary creation does not secure an attacker-controlled path prefix. The archive is an API reference, not a claim about the installed macOS version. Inspect man 3 mkstemp locally when checking that platform.

Ownership of the name begins immediately after successful creation. A temporary Descriptor guards the raw handle while close-on-exec is set; File::adopt_native then becomes the sole handle owner. If header writing fails, abort attempts both close and unlink. The existing partial-I/O loop writes every requested byte or throws; an exception does not imply that nothing reached the temporary file.

Numeric CSV needs no quoting for these unsigned fields. The maximum row contains two 10-digit and two 20-digit values, three commas, and one newline: 64 characters. A 96-byte stack array leaves space for the terminator. The explicit unsigned long long conversions match %llu; assuming uint64_t always aliases that exact type would make a variadic format call nonportable.

finish closes before renaming. Both names are in the same parent, avoiding a cross-filesystem rename request. A successful rename replaces an existing regular result name without writing a partial new prefix into that old file; see Apple's archived rename manual for the interface and filesystem constraint. The final name is the completion boundary for this local synchronous tool.

This sink does not synchronize file contents or the parent directory. It is not a durable database installation or a power-loss-safe result checkpoint. Ordinary failures before publication preserve an existing final result in our fault checks. A process exit can leave a temporary name. We neither adopt such a name on restart nor claim it contains a complete answer. Keep this boundary separate from Chapter 11's synchronized manifest protocol.

An aborted sink closes its descriptor and then attempts name removal. The cleanup functions record errors instead of throwing during unwinding.

An unlink refusal retains temporary_live_ and the path, records the first cleanup error, and permits explicit retry after the cause is removed. Error history stays visible after a later successful retry. Destruction tries cleanup again but cannot promise absence when the OS continues to refuse deletion. A published file is never unlinked by abort or destruction.

Return an owning error, not a borrowed exception reference

The complete-query API returns a status plus an optional error handle. C++'s std::exception_ptr owns a reference to an exception object; a default instance is empty. Inside catch (...), std::current_exception() captures the handled exception, and std::rethrow_exception later throws through a nonempty handle. The exception propagation reference specifies the object's retained lifetime and the null-handle precondition. We need only these long-established facilities, not newer features in that evolving draft.

This is already useful without threads: the driver can inspect counters before printing the original diagnostic. current_exception() is nonthrowing, but its implementation can substitute a memory-allocation failure exception when capturing requires unavailable storage. Do not present exception storage as a charged, allocation-free byte string or retain a reference to a caught stack variable.

make_query receives one captured view; the join factory copies that one ownership boundary into both scans. The first sort orders facts for joining. The second sort receives joined rows, not a fresh database scan. Finally, GroupAggregate consumes regional order. No source reopens a later snapshot between stages.

execute_query creates separate statistics owners, owns the resulting plan, consumes it, and marks complete only after sink completion. Reports can keep those statistics and the root ledger alive after files and input data are released. Failure to create the report's second statistics object is handled just like a later allocation failure. A caller's db.snapshot() executes before entering this function; exceptions while acquiring that argument belong to the caller's outer boundary, not the returned report.

A thin command-line driver

The driver accepts database, temporary parent, output parent, output basename, and two day bounds. It does not parse SQL. Day values are unsigned 32-bit integers, but the half-open upper bound may equal 2^{32} to include the last day. std::from_chars returns both an error code and the first unconsumed position; checking only the error would accept a prefix such as 2x. The integer conversion specification describes these two results. We require every character to be consumed and then check the day domain and interval order.

The optional tiny preset forces three-row runs, two-row frames, two-way merge, and one-group output for a small fixture. It is a mechanism test, not a production performance preset. Both sorts retain the 128-run cap, so this preset rejects more than 384 input rows per sort. Default chunk size 4096 allows at most 524,288 rows per sort with that same metadata cap. Increase explicit capacities only when the shared budget and machine support them; there is no silent unlimited mode.

The driver opens the database for recovery and captures a snapshot using the existing exclusive directory lock. It is not a read-only attachment to another live process: snapshot capture can seal/rotate the active log. This is a local single-process synchronous tool until the later runtime integration chapters.

The 64 MiB root is a covered-allocation limit, not a claim that process memory is 64 MiB. The reported peak includes database/query charges observed over this run; it is neither isolated operator memory nor RSS. Both sort statistics separately show whether spilling occurred. A complete result may still be accompanied by a cleanup warning: an unused temporary file's deletion failure does not retroactively change successfully computed values, but it must not disappear from diagnostics.

Checkpoint. Trace (1,3,100,500), (1,3,101,250), (2,3,102,700) through an output capacity of one. The first return emits (1,3,2,750) and retains the last row in the current group. EOF emits (2,3,1,700), and the following call returns empty EOF. Next replace the last group by amounts M and 1: the earlier owning batch is valid, the current output clears, the sink aborts, and no new complete result may replace the old one. Part 3 executes these distinctions.
