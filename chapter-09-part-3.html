Chapter 9 — Memory budgets and a pinned block cache

Part 3 — Reader integration and pressure tests

Part 1 supplies the common ledger; Part 2 supplies pins and eviction. Now connect them at Chapter 8's actual frame-loading boundary, rather than introducing a second reader that ignores the format checks. This is the final part of Chapter 9 and shares its 3.5-hour allocation.

A successful cache miss must mean more than "some bytes were read." Before those bytes can be shared, validate the frame length/tag/checksum, entry counts and bounds, key order, directory endpoints, record encodings, and Bloom membership. The cache stores a complete validated frame, including framing bytes. Hits can then avoid both disk access and a repeated full validation pass, provided all readers use the correct immutable file identity.

Replace a reusable buffer with an owning pin

Keep OwnedEntry unchanged. In include/strata/storage/table.hpp, replace the entire TableReader class definition, from class TableReader { through its closing };, with the following definition. Keep the enclosing namespace and header guard. Part 1 already added the block_cache.hpp include and changed the builder declarations; no other header definition needs replacement.

The reader borrows a budget and, optionally, a cache. Both must outlive it. The reader still owns its file and its metadata vector. Two readers sharing data blocks retain two charged metadata allocations; this chapter does not pretend to share metadata merely because their file IDs match.

Each cursor owns BlockPin pin_ instead of a reusable vector. buffer_capacity() now reports the capacity of its currently pinned frame, or zero when it has no pin. The frame is usually smaller than the configured maximum block size. This changes the observation method's precise meaning; it does not change the file format or entry()'s borrowing contract.

cached_ controls whether a cursor consults the cache. Public begin and lower_bound construct normal cached cursors. verify_all will construct an uncached cursor, because verifying stored bytes and trusting an earlier cached copy are different operations.

Replace the complete TableReader constructor in src/storage/table.cpp. The format checks are the Chapter 8 checks; the new initialization and binding check at the start make allocation ownership explicit:

When a cache is supplied, it must use this exact budget object and recognize the file ID. Without a cache, require ID zero: there is no cache namespace in which another number would have meaning. Both invalid bindings and metadata allocation failures unwind the moved-in file owner, so an unsuccessful construction does not leak a descriptor.

Notice the order before metadata_.resize(meta_size): fixed header/footer reads, file-bound checks, then the allocation. The byte ledger does not replace format validation. A corrupt claimed size must still fail its format bounds rather than consume the entire available budget.

The metadata reader still calls the existing read_frame helper. All its uses accept spans, so changing a vector's allocator does not require copying its contents into another vector. The old directory, filter, may_contain, begin, and lower_bound definitions remain unchanged.

Its first range comes from an already validated directory: frame length is at least a frame header, count, one entry header, and checksum. The size-equality check therefore precedes safe fixed-field reads. Every decoded row is validated before any row in that frame can be exposed.

Now add the loader that connects the file owner to the cache:

The lambda captures this, a pointer to the current reader, and a copy of d, the directory descriptor. It does not copy the reader or retain a borrowed local descriptor. Its reference arguments exist only during the synchronous call to get or BlockPin::load.

A failed partial read or failed validator throws before get calls admission. The incomplete candidate is destroyed and old cache entries survive. The block_reads_ counter now counts physical data-frame reads that passed the entire validator, rather than Chapter 8's earlier increment after CRC alone. Hits do not increment it; failed reads/semantic checks do not increment it. The fixture backend separately counts all low-level read attempts, including short transfers and failed calls.

A cache hit does not rerun this lambda. It reuses bytes previously validated for the same immutable file incarnation, offset, and size. Passing one file ID for two different files would break this reasoning even if their checksums were individually valid. An identity contract is not replaced by a checksum.

Finally add the new Cursor::load:

Clear the old visible entry and borrowed payload before dropping the old pin. That invalidates the cursor's previous row and stops this cursor from preventing its old block's eviction. Then acquire the new validated pin. If acquisition throws, current_ stays empty and the cursor is terminal; there is no half-visible new row and no promise that the previous row can be retried.

The old block may still be resident or pinned by another cursor. Releasing this cursor's handle does not authorize destroying somebody else's allocation. After success, payload_ borrows a subspan of the newly owned pin, and the first row is decoded from bytes already validated by the loader. The count cannot be zero because the validator rejected that case.

Finish the cursor state changes

Replace the complete cursor constructor. It still searches directory last keys, retaining Chapter 8's version-spanning correctness, but it no longer allocates a maximum-size private buffer before load:

Replace Cursor::next as well. Normal end-of-stream now releases its pin rather than retaining the final frame until cursor destruction. The conservative rule remains: treat every call to next as invalidating the previous EntryView. Do not retain its span just because some other owner happens to keep the same allocation alive.

Keep Cursor::entry and TableReader::find unchanged. A successful point lookup still copies its at-most-30-byte payload into OwnedEntry. In particular, a bypass pin can disappear on return from find while its returned row remains valid: the result owns different inline storage.

Replace verify_all with this complete definition:

This cursor does not call cache lookup or admission. Every block is read and validated anew using a charged temporary pin. A warm cache can continue serving its previously validated bytes after an injected disk fault; verify_all must still discover that fault. Verification needs headroom for its own block even when the cache is full, because it does not evict entries behind the caller's back.

There is a performance tradeoff: without a cache, each new frame now allocates an owning block rather than reusing one cursor vector. The uniform lifetime model is explicit and testable; it is not a claim that this version minimizes allocations for long scans. Cache hits do remove repeated frame allocations and I/O. Later measurements can separate those cases before optimizing exclusive buffer reuse.

Migrate the existing fixtures, not their assertions

All arena, memtable, builder, and reader constructors now require a budget first. For example, MemTable table{cap} becomes MemTable table{budget, cap}, and write_table(file, table, options) becomes write_table(budget, file, table, options). The application should own its budget in its enclosing engine context, not in a hidden singleton.

Use a bounded file fixture with multiple open readers

Create tests/cache_file_ops.hpp. This backend has 8192 fixed bytes and at most 15 simultaneous fixture descriptors. It returns at most seven bytes per transfer, so the real File::read_exact/write_all loops remain involved. Its storage is fixture memory outside the engine ledger; it is not a second storage engine.

open allocates no heap storage: it claims a Boolean descriptor slot. Two readers can therefore own independent file handles to the same immutable fixture bytes. fail_reads injects an I/O failure without making a cached hit fail. live_files checks that failed reader construction closes its moved-in file.

Test the ledger without depending on a library layout

Create tests/block_cache.cpp. The first helpers throw on a failed condition in both Debug and Release. The charge probes briefly construct real objects to measure this implementation's requests; they return numbers, not retained allocations. Budget objects are declared before their users so they are destroyed last.

block_charge(64) includes more than 64 requested bytes because the owning block and its shared-control storage also exist. metadata_charge(2) measures the actual fixed slot vector. These are local layout measurements, not constants to write into an on-disk format.

Test empty reservations, subtraction-based overflow protection, moves, assignment, and self-move. A maximum-size reservation is only a ledger operation; this test does not try to allocate SIZE_MAX physical bytes:

After reserving 12 then 4, move-assigning the 4-byte lease over the 12-byte lease must return the original 12 and leave exactly 4 reserved. The high-water mark remains 16. Checking only zero usage at final scope exit would miss an incorrect intermediate ownership transfer.

The allocator test checks capacity, failure cleanup, over-alignment, and propagation across two distinct budgets:

Swapping two vectors swaps the allocation owners and their allocator identities, not the physical allocations' ledger charges. The original budgets still account for their original allocations. Move-assigning over a destination must free that destination using its old allocator before it takes ownership of the source's allocation and allocator. The test makes those lifetime effects observable.

Trace pins, bypass, and the final owner

The next test uses a two-block resident limit. A and B are pinned; a miss for C must return a charged bypass without displacing either. Copying and moving C's pin must not allocate another block. Releasing only one copy must not return the charge early.

After B's reader pin disappears, B is still charged but evictable. A second miss for C now admits C by removing B. The first bypass was never installed, so the loader really runs again. Trimming after all reader pins disappear leaves only the slot metadata. Cache destruction releases that too.

The final scope in this function tests a different direction of lifetime: the cache disappears before its returned pin. Only the frame's own charge survives; its bytes remain accessible until that last pin is reset.

Fail before eviction, including the second allocation

The next function first reserves every remaining admitted byte. A hit still works because it shares existing storage; a cold miss throws BudgetExceeded before touching the old entry. Then a loader partially fills its private candidate and throws. That candidate must not appear in the cache.

Finally sweep the allocator failure ordinal from one upward until construction succeeds. This visits the control-storage and payload requests without asserting that every library combines shared allocations in the same way. The finite bound is a diagnostic guard for this small constructor; exhausting it fails the test rather than silently declaring success.

The old and fresh keys intentionally have the same offset and size but different issued file IDs. Their fill bytes differ. The fresh result must contain 42, not the old zeros. This exposes an implementation that accidentally drops file identity from the lookup key.

After every injected allocation failure, check both old membership and exact current usage. A global zero-at-exit check alone could overlook lost cache entries or a temporary reservation left attached to a live scope.

Enforce one budget across different subsystems

The next test makes the shared budget exactly one arena chunk. The first memtable uses it; the second memtable cannot acquire a chunk despite its larger local cap. A table builder cannot allocate workspaces against the same exhausted ledger and must not write a header when construction fails.

This is the integration that a cache-only payload counter would miss. Cache metadata also has to fit the common budget; a one-byte budget cannot create even one slot. A zero-slot cache and a cache whose byte limit excludes its own metadata are separate configuration errors, not allocation failures.

8 + 4 + 22 + 30 + 4 = 68\text{ bytes}.

The terms are frame header, entry count, entry header, event value, and CRC, respectively. Because two such rows would exceed the 64-byte payload cap, each row occupies a separate frame. The builder's metadata and workspace allocations must be gone before the reader/cache test starts.

The boundary test opens two readers under the same immutable file ID. Their first cursors must point into the same pinned frame, but their directory/filter metadata remains separately charged. Holding blocks 10 and 20 while looking up 30 forces a point-query bypass; the returned OwnedEntry survives after the bypass charge is released.

The test then distinguishes a hit from verification, injects media damage after warming the cache, checks a cold corrupt load never enters the cache, and forces a cursor advance to fail under a fully reserved budget. The intentional file-byte change is fault injection, not an allowed mutation of an immutable table.

left.next() can first succeed under exhausted headroom because block 20 is already resident. Its next advance needs absent block 30 and therefore fails. The cursor must become terminal, while another cursor's pinned frame remains valid. Deliberately break recency, not lifetime

Inside BlockCache::get, temporarily replace touch(hit); with a comment so a hit no longer updates recency. Do not change the loader, pin, or eviction code. Rebuild and run only the new test in Debug and Release:

Expected failure: budget/cache: hit did not refresh recency, with nonzero process status. A, B, hit-A, C should retain A and C. Without the touch, the implementation evicts A instead. Every allocation can remain valid and every charge can still balance, so a sanitizer report is not required for the defect to be real.

Restore touch(hit);, rebuild, and rerun the full twelve-test suite before continuing. The source listings in this chapter contain the correct function. Do not retain the diagnostic edit in the next chapter's prerequisite state.

A second prediction needs no code defect: while a resident block is pinned, call trim. The entry remains. Reset the pin and call trim again; the block charge is returned, leaving metadata until cache destruction. Explain the difference using owners, not the vague phrase "the cache freed the pointer."

Diagnose the boundary that failed

Symptom First boundary to inspect
Old tests reject constructor arguments A required first budget argument or the matching declaration/definition migration was missed.
Usage falls after vector.clear() The counter follows logical size instead of allocator-owned capacity.
Last bypass-pin release leaves bytes charged A shared owner still exists, or deallocation did not return its original ledger charge.
A failed miss removes an old entry Eviction happened before candidate construction/validation or before the feasibility pass completed.
A hit reads the file The loader is being invoked before lookup, or readers received different file IDs.
Replacing a file returns old rows File identity was reused for a different immutable incarnation, or omitted from the key.
verify_all misses damage after a warm hit Verification used the cache rather than the uncached cursor path.
Termination at budget destruction A lease/allocation outlived the ledger, or a release path is missing.

Do not respond to every BudgetExceeded by increasing a cap. Inspect retained metadata, resident blocks, live pins, and temporary candidate headroom first. A cache can satisfy its own resident limit while the shared budget is exhausted by another subsystem. A bypass can be correct while repeated bypass reads are an undesirable workload pattern. Those are distinguishable observations, not one undifferentiated "out of memory" symptom.

What the boundary now guarantees

The implemented ledger admits requested dynamic storage before acquisition and returns charges on matching release. The cache has bounded charged lookup/recency metadata, byte-based residency, immutable owning pins, stable file-incarnation keys, nonthrowing admission after successful preparation, and charged bypass. Failed candidate construction, I/O, or validation does not discard older entries. The reader shares a validated frame without weakening its parser, while full verification rereads stored bytes.

The limits remain explicit: single-threaded/exclusive use; no process-RSS cap; no accounting for hidden allocator overhead; no unbounded input or metadata container disguised by a payload counter; no automatic durable table installation; and no claim that a pin synchronizes concurrent cache mutation. A shared budget is a common admission domain, not a collection of mutexes or a filesystem log.

The next chapter connects prepared memtable changes to a framed write-ahead log. These allocation boundaries matter there: rejection before any log append is not the same state as an uncertain write after an irreversible external effect.
