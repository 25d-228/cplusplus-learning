Chapter 6 — Records, bytes, and a dependable file boundary

Part 2 — Deterministic faults and native checks

This is the continuation of Part 1, not another chapter or another time allocation. Retain the five engine files written there: core/record.hpp, core/checked.hpp, core/codec.hpp, io/file.hpp under include/strata/, and src/io/file.cpp. Earlier foundation sources and all six earlier CTest entries remain unchanged.

Part 1 defined 30-byte event and 14-byte account images, checked unsigned size and file-range arithmetic, and the move-only strata::io::File. Its borrowed FileOps backend performs one attempt; File finishes short transfers and retries interruption. IoError records the original offset and known completed count. EOF can yield a short read_up_to, while read_exact rejects truncation. The nonthrowing destructor attempts close once; explicit sync/close report failures. No operation promises to roll back bytes already written.

Here we give those contracts controlled counterexamples, complete the native fixture writer, compare bytes with an independent decoder, and add two tests. Every repeated filename block appends in order, as in Part 1. The full chapter's 3.0-hour estimate already includes these checks; the combined implementation is the prerequisite for Chapter 7.

Make short transfers and faults reproducible

The test backend is deliberately one 64-byte file, not a replacement filesystem. It owns fixed storage, a logical length, and a single live handle numbered 7. Counters and fault settings are single-threaded test state. Reopening this fixture keeps its bytes and counters; create a fresh backend for a fresh test.

A backend is declared before the File borrowing it, so reverse destruction order closes the file before destroying its operations object. open_fixture marks that slot live and transfers its handle through adopt; it performs no native open. There is no allocation, lock, or global failure injector in its virtual methods.

fail_after is a limit on cumulative accepted bytes, not attempted bytes or the absolute file offset. Setting it to 4 leaves the first four successful bytes and fails the next request. interrupt_write is a one-shot flag: std::exchange(flag, false) returns its previous value while clearing it. The initializer-list form of std::min takes the smallest of the three given size_t values; it is not allocating a vector.

The offset is checked before narrowing to size_t or subtracting it from a capacity. Reads return zero at or beyond used. An injected failed read does not modify its destination; that is this fake's defined behavior, not a claim that every native error preserves the unread suffix. fail_read_call counts attempts, including interrupted calls, and is compared with the incremented counter.

The fixed array begins zero-filled, making gap bytes predictable in our nonzero-offset examples. It is not an experiment in physical sparse-file allocation. Its close below consumes the logical slot even when it reports an injected error. This models the dangerous case in which a retry would act on a handle no longer owned by the caller.

The fake always rejects full_device; that verifies error propagation without pretending to simulate a storage controller. It does not track dirty versus persistent images, directory entries, process crashes, or device-cache ordering. Those require different experiments.

Check the contracts with small concrete inputs

The test program uses throwing checks so they remain active in Release builds. expect_throw<Error> runs a callable, accepts only the named exception family, and fails if the call returns normally. Other exception types propagate to main. expect_io checks the numeric error and progress fields, not a platform-specific what() string. These helpers are small templates using the callable and capture syntax from Chapter 5.

An unnamed namespace keeps these helpers local to the executable. The using declarations shorten names in that namespace only; the engine headers do not inject them into every including translation unit.

The codec fixture matches the first event/account example in the roadmap. For both schemas, try every shorter prefix, including zero and one byte, so a header access cannot hide ahead of a length check. Also test excess length, wrong version, unknown and wrong relation tags, full-width integers, zero values, and rejected narrowing that leaves its destination unchanged.

The temporary from encode_event(largest) lives until the end of that full expression; decode_event consumes its borrowed bytes during the call and retains no view. This use is safe, unlike returning a span into a local array. The test distinguishes numerical key order from serialized-byte order without using an invalid comparator.

A three-event reservation is 90 bytes. The boundary calls prove that addition, multiplication, totals, and file offsets take their intended error paths. The implementation does not need to allocate SIZE_MAX bytes to reject a count.

The exact four-call counts would catch forgetting to advance the offset, treating a short transfer as completion, or counting EINTR as progress. The empty requests and the rejected range must not increase either transfer counter. Calling close_checked twice and then destroying the owner must still yield one backend close call.

The file's logical end is 9: five preceding bytes plus four accepted bytes. The first failure is caught inside the file's scope to inspect that state; the final scope exit closes the handle. This is not resuming a database write after an uncertain commit. It is inspecting a deterministic low-level fixture.

The next check moves a file into an already-owning destination, tests self-move, rejects zero write progress, surfaces synchronization errors, and models an interrupted close whose handle has already been consumed:

The moved owner must keep the first backend, while assignment closes the second backend's old handle exactly once. destination is already closed when the injected EINTR escapes close_checked; its subsequent close and destructor must not repeat the attempt. The final deliberately thrown exception verifies cleanup during ordinary stack unwinding.

Passing these checks proves the wrapper's exercised state transitions under the fake's rules. It does not prove native close behavior under all signals or prove that every acquisition is released under every possible OS failure.

Write and reopen a real 44-byte fixture

The native path creates a new file, writes the event at offset 0 and account at offset 30, synchronizes in the requested mode, explicitly closes, and opens a new read-only owner. It decodes both records and checks for EOF at offset 44. No binary data is written through a C++ object pointer.

If synchronization fails, unwinding still attempts to close the writer; the program returns failure and may leave a partially or fully written pathname. It does not claim that failure left the filesystem unchanged. On success it leaves the fixture for independent inspection. No directory synchronization or atomic publication protocol is implemented here.

The entry point runs deterministic checks with no arguments, or writes the native fixture with --fixture PATH. A final full-device argument requests the stronger native operation explicitly. A request that is unsupported fails; it is not silently retried in the ordinary mode.

The IoError handler comes first because it is also a std::exception. It reports its extra context before the general handler. Both return failure. The normal no-argument checks do not need a filesystem path and do not open a native file.

Use a different implementation to check the bytes

Round-tripping through our own encoder and decoder could preserve the same mistake in both. Python's struct module supplies an independent encoding. The prefix < selects little-endian standard widths with no native alignment padding; B is one byte, Q eight, and I four. The event format is therefore <BBQQIQ, and the account format is <BBQI. See the official struct format documentation.

The script below either checks an existing fixture or creates an isolated temporary directory, invokes the C++ writer, checks its bytes, and deliberately tries to create the same name again. That second run must fail without changing the file. Python removes its temporary directory after the child processes finish; it does not implement the engine's I/O loop.

check=True turns an unexpected child failure into a Python exception. The intentional collision uses check=False, then tests its status and verifies unchanged bytes. Exact operating-system error text is not part of this oracle. Temporary-directory cleanup belongs to the test harness; it is not a claim that File owns or automatically removes names.

Add the library and two tests to the existing build

Append the following to the root CMakeLists.txt, leaving all earlier targets unchanged. Header-only codecs acquire their include path from strata-core; file.cpp is compiled once into that static library. strata-core-tests links the library rather than including the implementation source.

FindPython3 requests only the interpreter, not Python development libraries. $<TARGET_FILE:strata-core-tests> is a CMake generator expression that supplies the executable's actual path to the Python command. It avoids hard-coding a Debug-specific path. These mechanisms are documented by FindPython3 and add_test. No change to the earlier CMake version declaration is needed.

Keep the compiler already configured in those build trees. A new build tree can select the same native compiler with -DCMAKE_CXX_COMPILER="$CXX", as in Chapter 1. If CMake cannot locate Python, point -DPython3_EXECUTABLE at the compatible interpreter you actually use; do not install development libraries that this script does not require.

A logical defect can survive memory diagnostics

Temporarily change only the offset argument in File::write_all from offset + static_cast<std::uint64_t>(done) to offset. Leave the read loop unchanged. With two-byte writes, every call now overwrites the same position. The buffers remain in bounds, yet the file content is wrong.

Rebuild and run the deterministic check in both configurations. It must return failure, either at the exact-read boundary or the content check. A memory sanitizer may report nothing because the defect is in file positioning, not memory access. Restore the original advancing offset before proceeding and rerun all eight tests. This temporary defect is not prerequisite code.

For supported native compiler/runtime combinations, run the restored program under both AddressSanitizer and UndefinedBehaviorSanitizer:

The expected output is unchanged and there should be no sanitizer diagnostic. The deliberately caught IoError objects are test outcomes, not memory errors. See Clang's AddressSanitizer and UndefinedBehaviorSanitizer documentation for platform support and limitations. Instrumentation does not prove persistence, correct byte order, or an operating system's close semantics.

The important failure-state distinction is now concrete. Arithmetic and format validation can reject before mutation. A read can partly fill a private buffer. A write can leave bytes behind. A failed synchronization does not say that no data reached storage. Cleanup releases resources as far as its primitive permits; it does not reverse external effects.

What carries forward

Keep all eight new source/script files, the strata-core library target, and both new tests. The arithmetic helpers check sizes and ranges before use. The version-1 row codecs own their returned values and retain no borrowed buffers. The file owner has explicit move, close, synchronization, and partial-progress rules; test backends remain borrowed and must outlive it. The temporary wrong offset edit must be restored.

Next, the index will use KeyLess, checked allocation sizes, and stable resource ownership to build an arena-backed skip list. That chapter introduces aligned storage and explicit node construction before using them. The present layer remains independently runnable; no future index or log is needed to test it.

Technical references

The linked C++ working draft includes newer facilities, but the chapter uses C++20-compatible features. Apple archive pages describe the native interfaces; the installed SDK and runtime result determine the local capability.

  • Apple native interfaces: open, pread, pwrite, fstat, fsync, fcntl, and close.
