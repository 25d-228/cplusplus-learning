Chapter 11 — Flush installation and database reopening

Part 1 — Authority, identities, and the directory boundary

A synchronized table is not yet part of a database. Its bytes might be complete, but a new process still needs to know whether to use it, which log it replaces, and which other files must exist. Conversely, a perfectly readable old log is not permission to ignore a missing installed table. The database needs one explicit source of authority, and a protocol that changes that authority without losing its recovery dependencies.

This chapter builds a synchronous database around the existing skip list, table, cache, and write-ahead log. It installs complete manifest snapshots, rotates the active log, flushes sealed generations in order, owns a directory lock, and opens only the files named by validated authority. Current-state point reads make the integration observable. Immutable user snapshots and merged range reads remain the next chapter; this implementation is still single-threaded.

Learning objectives

Separate file contents from persistent names; encode a bounded authoritative catalog; distinguish active-log tail repair from sealed-log corruption; prepare all serving owners before publication; retain recovery dependencies across failed maintenance; and diagnose the difference between an exception, abrupt process exit, and a physical persistence failure.

Implementation allocation: 5.5 hours for all three parts. Allow 1.25 hours for manifest code, 1.75 for rotation/flush installation, 1.5 for the directory and reopen path, and 1.0 for integration and fault checks. Reading is separate. These are provisional implementation estimates, not a reason to skip an invariant.

Use the complete source state through Chapter 10, including Chapter 9's charged constructors and Chapter 10's truncate_to methods. Keep the fourteen existing CTest entries. This part creates storage/manifest.* and io/directory.* and adds native descriptor adoption to File. Part 2 explicitly extends WalMemTable and adds storage/database.*; Part 3 supplies all tests and build additions. Repeated filename blocks append in order. A block explicitly marked “replace” replaces that named definition, not the whole translation unit.

A catalog is not a directory listing

Suppose the directory contains an old log, a half-written table, and a temporary manifest. Sorting names and choosing the largest number does not answer whether any of those files became authoritative. A larger identifier means “allocated later,” not “successfully committed.” Reopening therefore reads exactly the file named MANIFEST. A missing or corrupt authoritative manifest is an opening failure. There is no “try the previous one” branch.

The permanent filename LOCK is a separate coordination object. The numbered namespace contains s-00000000000000000001.wal, similarly named .sst files, and .tmp manifest candidates. A temporary manifest is never an alternative recovery root. Numbered files not referenced by the manifest are orphans for this open: they may be unfinished outputs or retired dependencies. We count and preserve them, rather than interpreting or deleting them. Physical reclamation will need its own lifetime and high-water rules.

Creation and recovery are distinct operations. Recovery never creates an empty database merely because MANIFEST disappeared. Creation refuses a directory containing an existing manifest or any numbered engine file. An unsuccessful first initialization can consequently leave a directory that requires deliberate operator investigation, not automatic erasure and reuse. Unrelated files such as notes.txt are preserved.

The caller supplies an existing, trusted local directory. Durability arguments below assume that this directory and its parent-name binding are already stable. Opening it is not an implementation of recursively creating and synchronizing parent directories. The engine does not support network filesystems, hostile concurrent file replacement, or manual edits while it is open.

Give every installed source a sequence interval

A batch sequence is positive and strictly increasing. For a sealed log or a flushed table, write its covered sequence interval as (b,e]: the base b is excluded, the end e is included. The base is not a row to replay. A new active log with base 2 begins with no rows and reports sequence 2; its first batch must have sequence 3.

In this chapter each flushed generation produces one table containing all its versions, including tombstones. The manifest contains at most sixteen tables and four required logs, with the active log last. The other three log slots are sealed generations. Table intervals form a contiguous prefix beginning after zero. Sealed logs continue that prefix. The final active log has end == 0 as an open-end marker; its actual end is discovered by replay. Zero cannot be a sealed end because a sealed generation must contain a batch.

Let F denote the last flushed sequence. With T table entries and L log entries, validation follows one scalar boundary s:

s=0 \quad\longrightarrow\quad \text{each table requires }b=s,\ e>b,\ \text{then sets }s=e.

After the tables, require s=F. Apply the same rule to the first L-1 logs; finally require the active log's base to equal s and its end marker to be zero. These are the loops in validate_manifest, not a separate proof left for the reader to translate.

Here is the fixture's durable state progression. The temporary manifest names consume identities too, even though rename removes those numbered names.

Successful transition Table coverage Required logs Next identity
Create; then commit batches 1 and 2 None Log 1: base 0, active 3
Rotate None Log 1: (0,2]; log 3: base 2, active 5
Commit batch 3 None Same manifest; log 3 now contains batch 3 5
Flush the oldest sealed log Table 5: (0,2] Log 3: base 2, active 7

The final row advances F from 0 to 2. It does not flush batch 3, and it does not reset the active log's base to zero. The old log 1 can remain on disk without remaining a recovery dependency. Its contents are irrelevant to normal reopen.

Fix the manifest byte layout

This is a complete snapshot, not an append-only edit log. Every integer below is unsigned little-endian. Counts describe the active prefixes of bounded arrays; we never serialize C++ padding, unused array slots, or smart-pointer internals.

Offset Width Field
0 8 ASCII magic STRAMAN1
8 4 Format version, exactly 1
12 4 Table count T, from 0 through 16
16 4 Log count L, from 1 through 4
20 4 Reserved, exactly zero
24 8 Manifest epoch, positive
32 8 Next file identity, strictly above every referenced identity
40 8 Last flushed sequence F
48 32T Tables: identity, base, end, file length; four 64-bit words each
48+32T 24L Logs: identity, base, end; three 64-bit words each
48+32T+24L 4 CRC-32 over every preceding byte

The total encoded length is

N=48+32T+24L+4=52+32T+24L.

An empty newly created database still needs one active log: N=76 bytes. Two required logs use 100 bytes. One installed table and one active log use 108 bytes. At both caps, N=52+512+96=660 bytes. Counts are checked before their products determine an allocation or a span. The database checks the actual file length against this small limit before allocating its read buffer.

The epoch counts installed catalog transitions, not batches. Ordinary log writes do not rewrite the manifest. The CRC detects accidental byte damage; semantic validation detects a checksummed gap or duplicate identity. Neither authenticates the file or proves that a storage device persisted it.

TableRecord and LogRecord are value types with defaulted equality for checks. The default member values produce an uninitialized catalog, not an acceptable empty database: epoch == 0 and log_count == 0 must fail validation. Construction will explicitly supply the initial active log. The arrays keep metadata bounded without a dynamically growing catalog container.

next_id is a lower bound on future allocation. Gaps are harmless; reuse is not. The validator also rejects a referenced identity equal to next_id. File kind is not a second identity namespace: a log and table may not both claim the same identity in one manifest.

Create src/storage/manifest.cpp. The small require_manifest helper maps invalid persistent state to the already defined FormatError.

Validate coverage without building another index

take_id captures the fixed ids array and its used length by reference. Calling it checks one identity against earlier identities before appending it to that stack array. At most twenty identities exist, so this bounded quadratic check avoids an uncharged hash container and is not a database-size algorithm.

The table loop establishes the flushed prefix. The log loop deliberately does not set boundary to zero for the final active log: zero is a marker, not the next expected sequence. A missing sealed generation cannot be concealed by letting a later base jump forward. Table file sizes are format-bounded here; actual files and their contents are checked during opening.

Encode a validated value, then decode a bounded image

The encoder allocates one charged workspace. Its emit lambda advances a byte offset by eight after writing one word. Capturing at by reference is essential: a fresh offset on each invocation would repeatedly overwrite the first field. The vector remains alive while out borrows it and is not resized afterward.

For the 108-byte manifest after the first flush, the table words occupy bytes 48–79, the log words occupy 80–103, and the checksum occupies 104–107. Accordingly, at == 104 when the final put_le<4> runs. The zero-initialized vector and explicit reserved-field write give a deterministic image, independent of structure layout.

The decoder first checks the fixed envelope, then the checksum, bounded counts, and exact expected length. Only then can the take lambda advance through variable-count records. A valid prefix followed by trailing garbage is not a second supported format.

Returning a Manifest copies a bounded value. The encoded vector owns bytes; the decoded value retains no span into them. The caller may release the workspace immediately after decoding. The fixed arrays have unused slots, but only their validated active prefixes influence opening and future serialization.

Own the native directory and its lock

The existing File handles positioned data I/O through a FileOps backend. Directory enumeration and advisory locking are native descriptor operations, not simulated byte-file operations. Add a small native-only descriptor owner rather than passing a fake FileOps handle to flock or fdopendir.

The OS advisory-lock interface provides LOCK_EX | LOCK_NB: acquire one exclusive lock or report contention without waiting. It coordinates cooperating processes, not malicious writers. The lock file is never unlinked during normal shutdown. Unlinking it while one process still holds the old inode could let another process create a new inode and acquire an unrelated lock under the same spelling.

The directory owner is declared before all database data-file owners. Reverse member destruction therefore releases readers and logs first, then the lock and directory descriptors. Construction failure uses those same member destructors; there is no raw descriptor that waits for the failed complete object's destructor.

FileName has 27 characters: two for s-, twenty decimal digits, four for the extension, and one null terminator. This includes the complete unsigned 64-bit domain without allocating a string. Inventory holds only counts and the largest observed identity; it is not a collection of filenames.

OpenedFile transfers an ordinary File together with the length obtained from that very opened descriptor. Checking a pathname and subsequently opening it would otherwise separate the checked object from the used object. A trusted, exclusively managed directory is still an explicit precondition.

Keep native error and ownership policy in one place

Create the implementation below. openat resolves a single filename relative to the already opened directory, rather than rebuilding full paths throughout the engine. O_CLOEXEC, O_NOFOLLOW, and O_EXCL respectively address exec leakage, following a final symlink, and accidental reuse during creation. See the native open family for these flags. They are not a sandbox for an untrusted directory path; ancestor resolution and hostile file replacement remain outside the contract.

native_error copies errno before constructing an exception. check_regular rejects directories, special files, negative lengths, and multiply linked engine files. This also refuses a symlink discovered by fstatat without following it. Foreign names are not opened or deleted by the scanner.

An interrupted open is retried. A close is attempted once: blindly retrying a failed close can operate on a descriptor number reused by another operation. These are the same ownership principles used by File in Chapter 6.

The move constructor acquires other.release(); the source becomes -1. Move assignment first releases its old descriptor and guards self-move. release is a transfer operation, not a close. Its next use must immediately install the transferred handle in another owner.

Format and parse identities without wrapping

Append the filename generator. The loop writes decimal digits from right to left. FileName name{} initializes the final null byte even though the extension copy does not include a terminator.

An identity of 12 becomes s-00000000000000000012.wal. The twenty digit slots are always filled; the generator does not depend on locale or a platform's formatting of integer types. It rejects zero rather than reserving an ambiguous all-zero filename for the first log.

The parser ignores names outside s-, but rejects malformed names inside that reserved namespace. For a current partial value v, digit d, and maximum unsigned value U, require

v\leq\left\lfloor\frac{U-d}{10}\right\rfloor

before computing 10v+d. This is Chapter 6's check-before-arithmetic rule at a persistent identity boundary, not merely a printing detail.

starts_with is the C++20 counted-text operation on string_view. The view borrows the current directory entry's name only until the next enumeration step. No retained inventory field stores it. substr(22) is called only after the length check's short-circuit expression establishes 26 characters.

Acquire the lock before inspecting recovery state

The constructor rejects embedded nulls in the supplied path, opens the directory, opens or creates the permanent LOCK file, validates it, and acquires the lock before scanning. A competing process fails at flock; it does not parse a manifest while another process changes it. A failed constructor closes every already acquired descriptor through its fully constructed members.

There is no dependency on std::filesystem::directory_iterator or a vector of paths. The scan opens a new description of . relative to the directory. A simple dup would share directory-offset state; the independent open gives this stream its own enumeration position.

fdopendir takes control of its descriptor only on success. Until then, scan_fd owns it. After success, a unique_ptr with a local deleter closes the stream, which closes its descriptor. The directory-stream interface documents that ownership transfer.

readdir returns null for both end-of-directory and error. Setting errno to zero before each call distinguishes those cases. Closing the stream in a nonthrowing deleter does not replace this explicit read-error check.

The cap of 4096 counts all non-dot entries, including foreign names. It bounds enumeration work and prevents normal operation from silently accumulating arbitrarily many preserved orphans. Exceeding it fails open; it does not trigger unsafe automatic deletion. The C library's directory-stream bookkeeping is outside the engine allocation ledger, as are OS descriptor tables; the scanner itself retains no data-sized container.

Create exclusively, synchronize explicitly, replace only authority

open records a successful new name in its local entry count before any later validation can throw. Once the descriptor passes fstat, release transfers it into File::adopt_native. The returned owner now uses the established short-I/O, interruption, synchronization, and close policies; the directory layer does not implement a second set of transfer loops.

Append the two namespace operations. Only MANIFEST is replaced. A candidate log or table is created at a fresh identity and is never overwritten in place.

A successful rename changes the destination binding atomically for ordinary pathname lookup. That is not a claim about which binding survives power loss. The Linux fsync documentation explicitly separates file synchronization from synchronization of its containing directory. Our protocol therefore synchronizes data and names at different steps, and never treats an unsupported directory sync as success.

replace_manifest does not retry an ambiguous rename failure or remove the source candidate afterward. The caller will stop using the database and reopen its actual authority. When an existing manifest is replaced, two names become one, so the tracked directory entry count falls by one. Initial installation renames one candidate name to one authority name and does not change that count.

The directory code is infrastructure, not the persistence algorithm. In Part 2, the ordering of these operations will make a new log usable and a sealed log replaceable. A standalone call to replace_manifest has no such guarantee.
